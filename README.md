# UNO Online

Браузерная многопользовательская игра UNO. Полностью клиентская: HTML + CSS + JavaScript (ES6-модули) поверх Firebase (анонимная авторизация + Firestore). Готова к размещению на GitHub Pages.

Приоритет проекта — стабильность и предсказуемость: игровая логика вынесена в чистый детерминированный движок, покрытый 133 автотестами, а все ходы применяются атомарно через транзакции Firestore, поэтому игроки не могут разойтись в состоянии, сходить не в свою очередь или сыграть несуществующую карту.

## Возможности

- Классические карты: цифры 0–9, «Пропуск», «Разворот», «+2», «Wild», «Wild +4».
- Дополнительная карта «Обмен руками» — включается настройкой комнаты.
- От 2 до 10 игроков. Создание комнаты, вход по коду, выход, переподключение тем же игроком.
- Мгновенная синхронизация состояния между всеми участниками.
- Настройки комнаты: максимум игроков, таймер хода, карта «Обмен руками», плотность спец-карт (Маленькая / Средняя / Обычная / Большая — влияет только на количество спец-карт, обычные цифры не меняются).
- Механика UNO: кнопка «UNO!» при одной карте; если игрок не успел — соперники жмут «Поймать UNO», забывший берёт штрафные карты (без двойных штрафов).
- Таймер хода: по истечении времени игрок автоматически берёт карту, ход переходит дальше. Ход отключившегося игрока также авто-пропускается.
- Экран победы с таблицей и кнопкой «Играть снова».
- Чат, звуки (синтез Web Audio, без внешних файлов), адаптивный интерфейс, тёмная тема.
- Веер карт автоматически подстраивается: при 10/20/30/40 картах уменьшается шаг и, при необходимости, размер карт — ничего не выходит за экран и не перекрывает кнопки.

## Структура проекта

```
uno/
├─ index.html
├─ css/                 стили (переменные, база, меню, карты, игра, чат)
├─ js/
│  ├─ core/             чистый игровой движок (без DOM и сети) + константы
│  ├─ firebase/         подключение Firebase и онлайн-слой (комнаты, чат)
│  ├─ config/           firebase-config.js — сюда вставляется ваш конфиг
│  ├─ ui/               экраны и компоненты интерфейса
│  ├─ state/            локальное состояние (uid, никнейм, код)
│  ├─ audio/            синтез звуков
│  ├─ utils/            вспомогательные функции DOM
│  └─ main.js           точка входа
├─ firestore.rules      правила безопасности Firestore
└─ test-engine.mjs      автотесты движка (в поставке не используется)
```

## Настройка Firebase

1. Откройте [console.firebase.google.com](https://console.firebase.google.com/) и создайте проект.
2. В проекте нажмите значок `</>` («Web»), зарегистрируйте веб-приложение и скопируйте объект `firebaseConfig`.
3. Вставьте его в файл `js/config/firebase-config.js` вместо плейсхолдеров:

   ```js
   export const firebaseConfig = {
     apiKey: '...',
     authDomain: '...',
     projectId: '...',
     storageBucket: '...',
     messagingSenderId: '...',
     appId: '...',
   };
   ```

4. **Authentication** → «Get started» → вкладка **Sign-in method** → включите **Anonymous**.
5. **Firestore Database** → «Create database» → выберите регион, запустите в тестовом или боевом режиме.
6. Во вкладке **Rules** вставьте содержимое файла `firestore.rules` и опубликуйте.

## Запуск локально

ES-модули не работают по протоколу `file://`, поэтому нужен локальный веб-сервер. Из папки `uno/`:

```bash
python3 -m http.server 8000
# затем откройте http://localhost:8000
```

Чтобы проверить многопользовательский режим, откройте адрес в нескольких вкладках/устройствах: создайте комнату в одной и войдите по коду в другой.

## Деплой на GitHub Pages

1. Загрузите содержимое папки `uno/` в репозиторий GitHub.
2. **Settings → Pages → Build and deployment**: источник **Deploy from a branch**, ветка `main`, папка `/root` (или `/docs`, если положите проект туда).
3. Через минуту игра будет доступна по адресу вида `https://<логин>.github.io/<репозиторий>/`.

Так как `firebase-config.js` содержит только публичные ключи веб-приложения Firebase, его безопасно размещать в открытом репозитории — доступ ограничивают правила Firestore, а не секретность ключей.

## Запуск тестов

```bash
node test-engine.mjs   # 133 теста игрового движка
node test-hunt.mjs     # 377 краевых проверок + инварианты на 160 случайных партиях
node test-ui.mjs       # 59 headless-проверок интерфейса (через DOM-шим)
```

Всего 569 автотестов. `test-ui.mjs` использует `dom-shim.mjs` — крошечную реализацию DOM, чтобы прогонять реальные UI-компоненты без браузера.

## Ограничения (важно)

- **Скрытие рук.** Всё состояние партии, включая карты всех игроков, хранится в одном документе Firestore. Клиент показывает только вашу руку, но технически чужие карты видны в инструментах разработчика браузера. Для игры с друзьями это приемлемо. Истинное сокрытие требует серверной логики (Cloud Functions или отдельный сервер), которая раздаёт каждому игроку только его данные — в чисто клиентской архитектуре это невозможно.
- **Модель доверия правил.** Приложенные правила Firestore разрешают любому вошедшему игроку изменять комнату. Целостность ходов обеспечивается транзакциями и валидацией движка на клиенте, а не сервером. Более строгая защита от намеренного мошенничества также потребует серверной проверки ходов.

## Что протестировано

- **Движок, геометрия веера и UI-компоненты** — покрыты 569 автотестами (133 движок + 377 краевых с инвариантами на 160 случайных партиях + 59 headless-проверок интерфейса), включая стресс-прогон, раскладку руки на 1–40 картах и клики по картам/кнопкам. Запускаются через Node.
- **Онлайн-слой Firebase** (сетевая синхронизация, транзакции, presence, чат) написан и проверен ревью; живое подтверждение требует реального проекта Firebase и нескольких клиентов — выполните его после настройки: создание комнаты, вход, выход, переподключение, все спец-карты, большие руки (30–40 карт), телефон и ПК, несколько партий подряд.
