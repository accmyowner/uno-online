# UNO Online

Браузерная онлайн-игра UNO на чистом HTML/CSS/JavaScript (ES Modules) с синхронизацией через Firebase Realtime Database. Без сборщиков и своих серверов — готова к публикации на GitHub Pages.

## Возможности

- Комнаты по коду: создание и вход, синхронизация всех игроков в реальном времени.
- Лобби: код с копированием, список игроков, готовность, хозяин комнаты, настройки.
- Полная механика UNO: числовые и цветные карты, пропуск, смена направления, +2, смена цвета, +4; колода, сброс, добор, автоматическая проверка допустимости хода.
- Таймер хода (15–60 сек): по истечении автоматически берётся карта и ход передаётся дальше. Тайм-аутами управляет хозяин комнаты — партия не зависает.
- Настройки комнаты: лимит игроков (2–8), время хода, складывание +2/+4 (stacking), авто-удаление пустых комнат.
- Финал партии: таблица победителей с очками, кнопка новой игры той же комнатой (у хозяина) и возврат в лобби.
- Современный интерфейс: тёмная тема, glassmorphism, неоновая подсветка активного игрока, плавные анимации раздачи, добора, выкладывания, победы. Адаптивность от телефона до ПК.

## Настройка Firebase (5 минут)

1. Откройте [Firebase Console](https://console.firebase.google.com/) → **Add project** (можно без Google Analytics).
2. В меню слева: **Build → Realtime Database → Create Database**. Выберите регион, запустите в **test mode** (позже поставим правила ниже).
3. Слева вверху шестерёнка → **Project settings → General**. Промотайте до **Your apps**, нажмите значок `</>` (Web), зарегистрируйте приложение. Скопируйте объект `firebaseConfig`.
4. Вставьте значения в файл [`js/firebase-config.js`](js/firebase-config.js). Обязательно должен быть заполнен `databaseURL` (для Realtime Database он выглядит как `https://ВАШ-ПРОЕКТ-default-rtdb.firebaseio.com`).

### Правила базы данных

В разделе **Realtime Database → Rules** вставьте:

```json
{
  "rules": {
    "rooms": {
      ".read": true,
      ".write": true
    }
  }
}
```

Это открытые правила без авторизации — их достаточно для игры с друзьями. Пустые и старые комнаты удаляются автоматически при заходе на главный экран. Если проект будет публичным, добавьте Firebase Auth и ужесточите правила.

## Запуск локально

Из-за ES-модулей файлы нужно открывать через локальный сервер (не через `file://`). Любой вариант:

```bash
# Python
python3 -m http.server 8000
# или Node
npx serve .
```

Затем откройте `http://localhost:8000`. Чтобы проверить онлайн-режим, откройте игру в двух вкладках/устройствах и войдите по одному коду.

## Публикация на GitHub Pages

1. Создайте репозиторий и загрузите содержимое этой папки в корень.
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/root`.
3. Через минуту игра будет доступна по адресу `https://ВАШ-ЛОГИН.github.io/ВАШ-РЕПОЗИТОРИЙ/`.

Ключи в `firebaseConfig` не являются секретом — их видно в любом веб-приложении Firebase; доступ ограничивается правилами базы данных, а не сокрытием ключей.

```

js/state.js               # локальное состояние игрока
js/utils.js               # коды, id, тасование, буфер обмена
js/deck.js                # колода и чистые правила (проверка ходов)
js/engine.js              # игровой движок (ход/добор/пас/тайм-аут)
js/net.js                 # комнаты и транзакции Firebase
js/ui.js                  # карты, тосты, модалки, выбор цвета
js/home.js                # стартовый экран
js/lobby.js               # лобби
js/game.js                # игровой экран
js/main.js                # маршрутизация и подписка на комнату
test-engine.mjs           # автотест движка (необязателен для сайта)
```

## Проверка логики

Игровой движок покрыт автотестом: он проигрывает сотни случайных партий (2–8 игроков, с правилом складывания и без) и проверяет инварианты — карт всегда 108, нелегальные ходы отклоняются, зависаний нет, победитель определяется всегда.

```bash
node test-engine.mjs
```

## Как реализована надёжность синхронизации

- Все игровые действия проходят через **транзакции** Realtime Database над узлом партии — это исключает гонки и делает невозможным недопустимый ход (проверка выполняется внутри транзакции).
- **Тайм-ауты** обрабатывает только хозяин комнаты, с защитой по версии состояния — один ход не будет завершён дважды.
- Время хода считается от серверной метки с поправкой на смещение часов клиента (`.info/serverTimeOffset`), поэтому таймер одинаков у всех.
- При отключении игрок убирается из комнаты (`onDisconnect`), роль хозяина переходит к самому раннему участнику, пустые комнаты удаляются.
